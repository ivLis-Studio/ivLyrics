# 싱크 v6 저장 형식

PC와 서버의 코덱 원본은 `SyncDataCodec.js`다. 백엔드는 동일 파일을 `src/vendor/SyncDataCodec.cjs`에 포함한다. 원본 수정 후 `node scripts/sync-codec.mjs`로 복사하고 `--check`로 일치를 확인한다. PC·백엔드·iOS·Android의 `sync-v6-golden.json`은 동일한 고정 검증 벡터다. `scripts/sync-codec.mjs`가 네 저장소의 벡터를 복사·검사한다.

## 문서와 시간

```json
{
  "version": 6,
  "timeUnit": "ms",
  "indexUnit": "nfc-codepoint",
  "source": { "provider": "lrclib", "lrclibId": 123 },
  "lines": [{
    "id": "l0", "offset": 0, "length": 11,
    "timing": { "unit": "word", "startMs": 1200,
      "lengths": [6, 5], "deltaMs": [450], "endMs": 2200 }
  }]
}
```

`source`는 기존의 검증 가능한 LRCLIB ID, 원문 지문, 줄별 코드포인트 수, 재생 시간을 유지한다. 예시에서는 생략했다. 기존 생성기가 쓰는 NFC 정규화 코드포인트 기준을 명시했다. UTF-16 인덱스나 사용자에게 보이는 글자 묶음의 인덱스와 섞지 않는다.

시간은 0~86400000의 정수 밀리초다. 첫 시작 이후 `deltaMs`는 직전 타이밍과의 차이이며 0도 유효하다. 과거 파일의 밀리초 이하 정밀도는 조용히 반올림하지 않는다. v6 변환은 명확한 오류를 내고, 과거 데이터 조회는 원본 형식을 돌려준다. 편집기는 기존의 밀리초 기록 정밀도를 사용한다.

- `line`: `startMs` 한 개. `deltaMs`와 `lengths` 없음.
- `word`: `lengths`로 원문을 빈틈없이 나눈다. 공백도 반드시 한 구간에 포함한다. `deltaMs.length = lengths.length - 1`.
- `character`: `deltaMs.length = length - 1`. 객체나 소수 시간의 반복 대신 정수 배열을 쓴다.
- `mixed`: `runs: [{length, timing}]`. 각 run은 위 세 종류 중 하나이며 중첩하지 않는다. 한 단어를 글자 단위로 수정해도 나머지 단어의 단위가 유지된다.
- `endMs`: 마지막 음의 명시적인 종료 시각. 해당 타깃 마지막 시작 이후 최대 60초.
- `declared: false`: 단위를 지정하지 않은 과거 데이터를 보존할 때만 사용한다. 코덱 변환 자체로 글자 단위 점수를 올리지 않는다.

줄 ID는 원문 내 시작 offset을 base36으로 바꾼 `l<offset>`이다. 같은 원문에서 타이밍·스타일만 바꾸면 유지된다. 원문 자체가 바뀌면 검증된 source 지문도 바뀐다. 줄 병합·분할은 영향받는 ID의 삭제·추가로 표현한다.

## 보컬과 스타일

각 줄의 `meta`에 보컬·효과 메타데이터를 두고, `styles[].range`, `hidden`, `continuations`, `parallel.parts[].ranges`는 줄 내부의 인덱스를 사용한다. 범위는 `[시작, 끝 제외)`다. 파트마다 자기 `timing`, `id`, `role`, `join`을 갖는다. 미완성 작업 파트는 `pendingUnit`만 가질 수 있고 최종 제출 검증은 계속 타이밍을 요구한다. `parallel.splits`는 기존과 같이 줄 내부 경계다.

모든 문자가 정확히 한 보컬에 속하고 부모의 타이밍을 완전히 복원할 수 있으면 부모 `timing` 대신 `derivedTiming`에 단위·경계·끝 시각만 둔다. 겹침, 숨겨진 틈, 별도의 부모 타이밍이 있으면 부모 타이밍도 저장해 정보를 잃지 않는다. 줄 최대 2000 코드포인트, 문서 최대 5000줄·총 타깃 길이 100만, 파트 최대 16개의 상한을 코덱과 서버가 검사한다.

## 저장과 작업 추적

최종 `/lyrics/sync-data` POST는 실제 v6 문서만 받는다. 숫자만 6으로 바꾼 과거 구조는 400, 구규격은 426과 `code: SYNC_UPDATE_REQUIRED`, `minSyncVersion: 6`을 반환한다. 차단은 앱 버전 문자열에 의존하지 않는다.

작업 API는 모든 요청에 `formatVersion: 6`을 요구한다. 시작은 전체 v6 스냅샷, 이후는 `baseHash`, `resultHash`, `patch: {put, remove, meta?}`를 보낸다. 해시는 검색 UI 힌트를 제외한 정렬된 canonical 문서의 SHA-256이다. `put`에는 바뀐 줄만, `remove`에는 없어진 줄 ID만 보낸다. 하트비트는 데이터 변경 없이 세션·sequence·해시·활동 시간만 보낸다.

요청 전 event ID, sequence, 정확한 요청 본문을 디스크에 남긴다. 서버는 중복 event ID 검사를 오래된 기준 해시 검사보다 먼저 한다. 응답 유실 후 같은 본문을 재전송해도 한 번만 처리한다. 다른 기준 해시·같은 ID의 다른 본문은 409다. 원문 교체 검증, 수동 입력 증거, 과거 누적 시간과 이미 획득한 점수의 보존 정책은 유지한다.

IndexedDB 작업 큐는 기준 스냅샷과 변경분을 저장한다. 초안 이력은 10개마다 독립 체크포인트, 그 사이에는 줄·편집 상태 변경분을 저장한다. 현재 초안이 이력과 같으면 ID로 참조한다. 공개 초안 API는 기존 recordVersion 1을 유지하고 저장 전용 `storageEncoding: 6`에서 복원한다. 손상된 변경분 뒤에는 다음 독립 체크포인트부터 다시 복구한다. 기존 초안과 작업 큐도 읽는다.

## 조회 호환과 배포

기존 조회는 v5 호환 문서로 응답한다. `?format=6`을 요청하는 새 PC·iOS·Android는 v6를 받는다. 캐시 키와 무효화도 두 형식을 구분한다. iOS·Android 구버전은 기존 조회와 v5 파서를 계속 사용하므로 기존·새 싱크를 읽을 수 있다. 업데이트된 모바일은 자체 Swift/Java v6 파서로 정수 밀리초·라인·단어·글자·혼합 단위를 직접 읽는다. 라인·단어의 반복 시각을 글자 배열로 영구 확장하지 않고, 압축된 타이밍 컬렉션을 재생 모델에 사용한다. 글자 타이밍은 정수 배열을 유지하고, 단위별 범위·정밀도와 보컬별 끝 시각을 보존한다. 모바일 캐시 이름은 `sync-data-api-v3-v6`로 분리하며 저장 내용은 원본 v6 JSON이다. 과거 내보내기 파일을 가져와 수정하면 v6로 내보내고 저장한다. 재생·기존 편집 알고리즘은 경계에서 기존 뷰를 사용하며, 이번 변경은 UI 전체의 데이터 모델 교체가 아니다.

배포 시 `20261106000200_sync_v6_content_hash.sql`을 먼저 적용하고, v6를 읽고 쓰는 PC 릴리스와 서버를 같은 업데이트로 배포한다. 이 서버가 배포되는 즉시 과거 PC 저장 요청은 업데이트 안내로 거절된다. 기존 저장 행은 일괄 삭제하거나 점수를 재계산하지 않는다. 과거 blob을 물리적으로 바꾸려면 백업 후 백엔드의 `scripts/convert-sync-v6.mjs`로 변환 계획을 검토한다. 이 변경 작업에서는 운영 DB 변환·배포를 실행하지 않았다.

## 용량 비교의 범위

v5에도 `encodeSyncCreatorCompactTiming`으로 라인·단어를 압축하는 경로가 있었다. 따라서 전부 글자 배열이었다고 가정해 절감률을 계산하면 과장된다. 100줄, 줄당 같은 44개 코드포인트의 영문 문장, 일정한 간격으로 만든 합성 예시를 실제 v5 압축 함수와 비교하면 다음과 같다. 운영 곡의 분포나 서버 전송 압축 설정을 측정한 결과는 아니다.

| 단위 | v5 JSON | v6 JSON | v5 gzip | v6 gzip |
| --- | ---: | ---: | ---: | ---: |
| 라인 | 6,028 B | 8,162 B | 942 B | 1,032 B |
| 단어 | 15,676 B | 15,562 B | 3,072 B | 1,140 B |
| 글자 | 38,736 B | 22,762 B | 11,551 B | 1,168 B |

v6의 단순 라인 문서는 ID·형식 정보 때문에 더 클 수 있다. 글자 정수 차이 저장, 정확히 복원 가능한 부모 타이밍 생략, 부분 단위 보존, 작업 전송·초안 이력의 변경분 저장은 각각 별개의 개선이다. 혼합 구간의 `endMs`는 타깃 맨 끝에만 둔다. 중간 run의 독립 종료 시각은 기존 재생 모델에서 보존할 수 없어 허용하지 않는다.
